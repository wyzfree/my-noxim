# 固定总PE多芯片基准实验（2026-04-16）可复现实验说明

## 1. 实验目的
在**总PE固定为1024**的前提下，对比不同芯片划分在单进程（ChipIO）模式下的执行时间与交互正确性：

1. `1 chip x 32x32`
2. `4 chips x 16x16`
3. `16 chips x 8x8`

本实验的核心不是“多芯片一定更快”，而是回答：

1. 在公平输入负载下，不同划分的性能趋势是什么；
2. 修复后，多芯片之间的数据交互是否正确。

## 2. 为什么这样设计（公平性原则）
为避免“比较不公平”，本实验做了以下控制：

1. `chips * dimx * dimy = 1024` 恒定；
2. 所有组 `sim=12000` 一致；
3. 所有组都使用显式生成的 `cross_traffic`；
4. 每个 `chips+sparsity` 组合重复3次；
5. 使用 `strict_fair=1`，使同一稀疏度下目标注入条目数一致：
   1. `sparsity=0.05 -> target_entries=256`
   2. `sparsity=0.15 -> target_entries=768`
   3. `sparsity=0.30 -> target_entries=1536`

## 4. 本次实验的实际运行指令
在项目根目录执行：

```bash
cd /home/st1101/wyz/noxim
conda run -n paper bash scripts/run_chip_partition_benchmark.sh \
  --sim 12000 \
  --repeats 3 \
  --timesteps 5 \
  --interval 2000 \
  --sparsities "0.05,0.15,0.30" \
  --chip-configs "1:32:32,4:16:16,16:8:8" \
  --strict-fair 1
```

说明：

1. 该脚本会自动生成带时间戳的新结果目录；
2. 本次目录为：`results/chip_partition_benchmark_20260416_185908/`；
3. 共运行 `3(chips配置) * 3(sparsity) * 3(repeats) = 27` 组。

## 5. 关键参数说明（论文可直接引用）
脚本参数与含义：

1. `--chip-configs "1:32:32,4:16:16,16:8:8"`：固定总PE、改变芯片划分；
2. `--sparsities "0.05,0.15,0.30"`：控制注入稀疏度（低/中/高负载）；
3. `--timesteps 5` 与 `--interval 2000`：控制注入时刻分布；
4. `--sim 12000`：每组仿真周期；
5. `--repeats 3`：重复实验用于统计均值与波动；
6. `--strict-fair 1`：确保不同芯片划分在同稀疏度下负载总量一致。

## 6. 输出文件说明
本次结果目录：

`results/chip_partition_benchmark_20260416_185908/`

核心文件：

1. `benchmark.csv`：27组原始结果（逐次运行）；
2. `run.log`：完整日志（含每个chip统计）；
3. `interaction_validation_report.txt`：交互正确性校验结果（mismatch统计）；
4. `benchmark_tidy_by_condition.csv`：按 `chips+sparsity` 汇总；
5. `benchmark_tidy_overall.csv`：按 `chips` 总体汇总。

## 7. 结果摘要（本次实测）
`benchmark_tidy_overall.csv`（跨所有sparsity）：

1. `chips=1`：`avg_wall_time_sec=56.4989`
2. `chips=4`：`avg_wall_time_sec=55.6444`，`speedup_vs_1chip_overall=1.0154`
3. `chips=16`：`avg_wall_time_sec=58.1256`，`speedup_vs_1chip_overall=0.9720`

`benchmark_tidy_by_condition.csv`（分稀疏度）：

1. 4芯片相对1芯片在三个稀疏度下都略快（约1.0%到2.9%）；
2. 16芯片相对1芯片在三个稀疏度下略慢（约2.3%到3.1%）。

## 8. 交互正确性结论（修复验证）
`interaction_validation_report.txt` 结果：

1. `total_runs=27`
2. `parsed_runs=27`
3. `mismatches=0`

含义：每组实验中“各芯片收到的packet数”与对应traffic文件中 `dst_chip` 计数完全一致，说明修复后芯片间交互正确。

## 9. 复现实验时的推荐流程
1. 先运行主脚本生成新目录；
2. 检查新目录 `benchmark.csv` 中 `exit_code` 是否全为0；
3. 检查 `run.log` 中是否出现 `Noxim simulation completed`；
4. 进行交互一致性校验（建议保留 `interaction_validation_report.txt`）。
